# What heai-tools can take from the wider ecosystem

*Idea report, 2026-09-11. The three earlier studies read one repository each. This one reads the field: the conventions coding agents have converged on, the workflow engines that have already paid for their scars, the ownership and policy tools that predate all of it, and the evaluation practice that decides whether a prompt change was real. It is organized by which file in the project directory each finding lands in, the same shape as [project-directory-rehash.md](project-directory-rehash.md). Not a commitment.*

*Sources are primary documents and specifications, linked inline. Where a claim could not be verified this session it is marked **[unverified]** rather than repeated; several vendor documentation sets have been restructured recently and older blog descriptions of them are stale. Several findings were checked against this repository's own source rather than taken on trust, and where the research and the code disagree the code wins and the section says so.*

## The short version

Five things are worth taking, and they are small: a filename, four YAML keys, a field set, a hash, and a body template. Most of what the field has built is distributed-systems machinery for problems a single-user, file-based system does not have, and importing it would be pure ceremony. Two places where heai-tools is already ahead of mature tools are worth defending, not traded: glob-set non-overlap in the map, and the one-file-per-record tracker.

## 1. The one convention worth adopting outright

**[AGENTS.md](https://agents.md/)** is a plain-markdown file an agent reads from the nearest directory upward. It specifies nothing but the filename and the precedence rule - the closest file wins, and an explicit user instruction overrides it. It came out of Codex, Amp, Jules, Cursor and Factory, is now stewarded by the Agentic AI Foundation under the Linux Foundation, and is read by a long list of harnesses including Copilot, Cursor, Devin, Zed, Warp and Aider. The same idea appears under other names everywhere: Aider's `CONVENTIONS.md` loaded with `--read`, OpenHands' `.openhands/microagents/repo.md`, Cline's `.clinerules`.

There is nothing to implement, which is the point. `heai-architect context <actor>` already prints markdown - checked against the sample project, it emits a `# actor:api-owner` heading and the actor's context prose. What it does not print is the scope itself. Adding the territories' globs and the request protocol to that output, and writing it to `AGENTS.md` at the repository root or one per territory directory, makes every harness that has never heard of this project read its ownership map for free. That is `scripts/agents/build.sh` from the previous report, with a better output target than `.claude/agents/*.md`.

This is also the honest answer to "should the tools speak MCP". They should not, yet: see section 7.

## 2. `architecture.yaml` - the map

The comparison that matters is with **[CODEOWNERS](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners)**, and it is favourable. CODEOWNERS is gitignore-syntax, and *"order is important; the last matching pattern takes the most precedence"*. That one rule produces every failure it is known for: a broad `*.js @web` placed below `/payments/ @pay` silently steals payments' JavaScript, and nothing in review shows it; exactly one pattern ever applies, so a path has one owner set and never a union; there is no `!` negation, so "everything in `src/` except `src/vendor/`" is inexpressible without ordering tricks; invalid lines are skipped silently; the file is capped at 3 MB. GitLab's variant adds `[Sections]`, per-section required-approval counts and `!` exclusions, which fixes the union problem and not the ordering one.

heai's map makes ownership a property of the pattern set rather than of the file's line order, and proves non-overlap as a glob-language property rather than against the files on disk. That is the actual invention here and it should not be traded away. Three additions are worth making around it. Checked against `tools/architect/schemas/architecture.schema.json`, a territory today carries exactly `parent`, `owner`, `scope`, `dependsOn`, `undeclaredDependencies` and `context`, so all three are genuinely absent.

**Tags, and dependency edges between tags.** `dependsOn` names territories one at a time, so a map with thirty territories needs a quadratic number of hand-written edges and will drift. [Nx's module boundaries](https://nx.dev/features/enforce-module-boundaries) solve this with tags and constraints - `{sourceTag: "scope:admin", onlyDependOnLibsWithTags: ["scope:shared", "scope:admin"]}` - so adding the fortieth library changes no rule. [import-linter](https://github.com/seddonym/import-linter) adds two contract shapes on top that a plain allow-list cannot express: `layers`, an ordering where every lower layer is implicitly forbidden from importing upward, and `independence`, one declaration that a set of siblings must not depend on each other in either direction. Both are derivable from tags. Its documentation page 404s at the moment, so the exact key names are **[unverified]** and should be re-read before copying.

**An export side.** Today only the consumer constrains an edge: a territory lists what it may depend on, and the territory being depended upon cannot say who may depend on it. Every mature system has the other half - Bazel's `visibility = ["//foo:__subpackages__"]` with deny by default, Go's `internal/` rule deriving a default-deny scope from the path with zero configuration, Rust's `pub(crate)` and `pub(in path)`. A `visibility:` field on a territory lets an owner restrict inbound edges without editing every consumer.

**A baseline.** ArchUnit's [`FreezingArchRule.freeze(rule)`](https://www.archunit.org/userguide/html/000_Index.html) records existing violations and reports only new ones. This is the mechanism every architecture tool grows, and its absence is the standard way they die: `check --strict` fails on first contact with a real repository and gets switched off. There is no baseline concept anywhere in `tools/architect/src`.

Two smaller things. From Backstage's [catalog descriptor](https://backstage.io/docs/features/software-catalog/descriptor-format), whose entity model is a near-isomorphism of the map - Component to territory, `subcomponentOf` to parent, `spec.owner` to owner, `dependsOn` identical - the fields worth stealing are `type` and `lifecycle`, which are cheap and can default the postures. Note the structural difference in heai's favour: Backstage distributes one `catalog-info.yaml` per repository and therefore cannot check non-overlap at all. And there is no ownership attribute in [OpenTelemetry's service conventions](https://opentelemetry.io/docs/specs/semconv/registry/attributes/service/); `service.namespace` is described as "for example the team name", which is not a standard to wait for.

## 3. `gate`, and what not to rebuild around it

Three mature things heai should not rebuild, each with a URL and a reason:

- **Pull-request comment plumbing.** [reviewdog](https://github.com/reviewdog/reviewdog) already has the reporters (`github-pr-review`, `gitlab-mr-discussion`, `local`), the filter modes (`-filter-mode=added|diff_context|file|nofilter`, default `added`), a `-fail-level`, and a JSON input format, rdjson, carrying ranged comments, severity and suggested fixes. Make `check` and `gate` emit rdjson and the entire posting problem disappears. This is design principle 5 working as intended: anything outside the repository is a plugin.
- **Intra-file rules.** [Semgrep](https://docs.semgrep.dev/writing-rules/rule-syntax) is a decade of work on `patterns`, `pattern-inside`, `metavariable-pattern` and `fix`. The map is about which files, never what is inside them.
- **A policy engine.** [Conftest](https://www.conftest.dev/) and OPA evaluate a document against Rego rules; [Cedar](https://docs.cedarpolicy.com/policies/syntax-policy.html) is genuinely close in shape to the gate - principal, action, resource, with `forbid` always beating `permit` - but none of them can express the hard part, which is proving properties *of the pattern set*: containment, disjointness, acyclicity. Rego expresses those badly and slowly. The right split is to ship the JSON Schema the tool already has and let a team layer Conftest on top for its own conventions.

Do not let the gate grow into a commenter. Every commercial LLM reviewer has converged on the same three mitigations - severity thresholds, path filters, and learning from dismissed comments - because the failure mode is comment volume and the outcome is being muted. [CodeRabbit's configuration](https://docs.coderabbit.ai/guides/review-instructions) is instructive for a different reason: `reviews.path_instructions: [{path, instructions}]` is the territory `context` block under another name, so a generator from the map to `.coderabbit.yaml` is a short script with real payoff. Greptile's documentation was unreachable, so its specifics are **[unverified]**.

Two concrete gate details. Normalize paths - `../`, symlinks, case - before matching; CODEOWNERS' case-sensitivity bug class applies to any glob matcher. And [git's trailer mechanism](https://git-scm.com/docs/git-interpret-trailers) is a better channel for attribution than a flag: configure `trailer.territory.key` once, have the agent stamp `Territory:` and `Actor:`, and read them back with `git log --format='%(trailers:key=Territory,valueonly)'` instead of passing `--actor` and hoping it matches who actually committed.

## 4. `tasks`

Three additions, all cheap, none of which needs a graph store.

**`blocked_by: [slug]` and a derived "ready".** Nobody who solved this invented storage for it. [backlog.md](https://github.com/MrLesk/Backlog.md) puts `dependencies: [task-1, task-2]` in the frontmatter and derives `--ready` as "dependencies all closed". [Beads](https://github.com/steveyegge/beads) has the richest vocabulary, splitting blocking relations (`blocks`, `parent-child`, `waits-for`) from non-blocking annotations (`related`, `discovered-from`, `caused-by`, `supersedes`), and rejects cycles at write time. heai already has stable slugs, `INDEX.md` is already generated in pick-up order, and cycle rejection at write time is what `new` and `set` already do for everything else. This is a sort-key change. Note what it does *not* replace: cross-flow waiting stays `flow`'s `--waits-on`, because that is about runs, not about work items.

**A `resolution` key.** Jira keeps status and resolution orthogonal, and heai currently conflates them: `done` and `canceled` are sibling statuses, so every new way of not doing something adds a status. `resolution: completed | wont-fix | duplicate | obsoleted-by` stops that multiplication.

**An honest empty `territory`.** Linear's Triage is an inbox for issues with no owner yet. heai's `territory` has no legal empty state, so a task that nobody has routed has to be mis-routed. One value, or one status, meaning "a human must route this".

**A body template, thin.** Spec-driven development is active and real - [Spec Kit](https://github.com/github/spec-kit), [OpenSpec](https://github.com/Fission-AI/OpenSpec), and Kiro, which is GA and shipping despite the rumour otherwise - but the three-artifact pipeline duplicates the architecture map and rots. Four lines of it are worth everything else. Spec Kit's task line carries a stable id, a parallelism marker and a back-link to the requirement: `- [ ] T012 [P] [US1] Create Entity model in src/models/entity.py`. Its requirement template marks its own gaps inline with `[NEEDS CLARIFICATION: auth method not specified]`. Kiro's EARS acceptance lines - `WHEN <condition> THE SYSTEM SHALL <behavior>` - are the thing that makes a task checkable by someone other than its author, which is exactly the problem when an agent hands work back from a container. So: `## Intent`, `## Acceptance` in EARS form, `## Out of scope`, `## Open questions` carrying `[NEEDS CLARIFICATION]` markers. A greppable marker that means "a human must answer before this runs" pairs directly with `by: [human]`.

**The cautionary tale.** Beads is the most-cited git-native tracker built for coding agents, and it abandoned files: the source of truth is now a versioned SQL database, `.beads/embeddeddolt/` is gitignored, and its documentation says plainly that the JSONL export is "not the source of truth or a backup". It has rewritten its storage layer once already. The two pressures that did it are worth naming because they are the ones that would do it here: hash identifiers, and semantic merge. Beads moved from sequential to hash ids precisely because two agents independently creating "#7" merge into duplicate ids - heai's slugs already dodge that - and the merge pressure is what one-file-per-record answers. Task Master, by contrast, keeps every task in one `.taskmaster/tasks.json`, documents no mitigation for concurrent writers, and has had no commits in about four months.

Do not adopt a `.gitattributes` merge driver for the tracker. Git's own documentation warns that `merge=union` "tends to leave the added lines in the resulting file in random order", and GitHub's web merge ignores merge drivers entirely. Regenerate `INDEX.md` after a merge instead, which is what `build` already does.

## 5. `flow`

The research here is the most valuable of the five, because the serious workflow engines have already paid for these mistakes.

**A definition edited while flows are open.** This is open question 1 in [project.md](../project.md) under another name. Temporal's answer is extreme and inapplicable: workflow code *is* the state, so any edit makes replay diverge and the execution dies, which is why `Patched` and worker versioning exist. Nothing in flow replays code, so none of that applies. [Step Functions](https://docs.aws.amazon.com/step-functions/latest/apireference/API_UpdateStateMachine.html) is the right model - *"running executions will continue to use the previous definition"* - and is honest that even new executions may briefly use the old one. flow already pins a copy of the definition per flow, which is that behaviour. What is missing is the loud failure: journal the definition's hash at start, and have `settle` refuse, visibly, any flow whose current definition no longer contains the state it sits in or the transition it needs. Refuse-and-report is most of the value; file-level version pinning is not needed.

**A step that must not run twice - and the sharper problem underneath it.** The research proposed an exclusive `mkdir` on an action key. Reading `tools/flow/src/actions.ts` shows the situation is the inverse of what it assumed. Actions fire only from a journal line that was just appended, from `createFlow`, `advance` or `settle`, and nothing ever rescans, so a hook cannot double-fire today; the action record is already keyed `<seq>-<state>`. The real exposure is a *lost* hook: if the process dies between appending the line and spawning the script, nothing ever notices, and the flow sits in a state whose entry script never ran. The fix and the risk arrive together. A recovery sweep - every entered line with no action record - is what makes flows survive a crash, and it is exactly what introduces the double-fire the exclusive key then prevents. Build them as one change or neither.

**Failure has nowhere to go.** A hook that exits non-zero leaves its code in `actions/` and parks the flow silently; `stuck` finds it within the hour, which is a long hour. [ASL's](https://states-language.net/spec.html) `Catch` block is the missing key: `on_failure: <state>` on a hook, so a permanently failed script moves the flow into a visible failed state. A per-hook `timeout:` is the second. Retry is third and should default to off - Argo Events defaults to no retry on triggers for a stated reason, that the sensor cannot know whether a retry would cause unexpected results, and heai's hooks spawn agents and mutate git, so that reasoning applies exactly. If retry is added, take ASL's field names rather than inventing: `IntervalSeconds`, `MaxAttempts`, `BackoffRate`, `MaxDelaySeconds`, `JitterStrategy`. Of Temporal's four timeout kinds, three exist because of worker fleets that do not exist here; only start-to-close is missing.

**Entry hooks without exit hooks leak.** This is the one genuine gap that statecharts expose. Scoring [SCXML](https://www.w3.org/TR/scxml/) honestly against a flat machine: hierarchy is replaced by parent and child flow links plus `trace`; parallel regions are replaced by `requires: {waits-on: {all: [...]}}`; history states are not needed until there is a pause-and-resume state. But the separation of fire-and-forget actions from invoked activities that start on entry and *stop on exit* is real and missing. The moment a hook starts something long-lived - an agent session, a dev server, a tunnel - nothing stops it when the flow leaves the state, and processes leak. One key: an exit hook beside the entry one.

**Approvals that a later edit invalidates.** This is the finding worth the most, and the answer is that no approval product does it. HumanLayer's shipped schema is `{run_id, call_id, spec, status{requested_at, responded_at, approved, comment}}` - no expiry, no content hash, and identity is whoever controls the Slack channel; its vendor has since pivoted away from the approval SDK entirely. GitHub Actions binds approval to a run and an environment, with no commit SHA in the payload, and gets away with it only because a new push makes a new run. The mechanism that actually does the job is [branch protection](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-protected-branches/about-protected-branches): dismiss stale approvals when new commits are pushed, and require approval of the most recent push by someone other than the pusher. So the pattern for a `by: [human]` transition is to record the git blob hash of the artifact approved, the commit it was approved against, and an expiry, and to refuse the transition when the hash has moved or the clock has run out. Identity comes from a signed commit, which offline is strictly stronger than a button in a chat channel. Note the corroboration from two unrelated directions: ECC's newest skill hashes drafts so that "a stale approval cannot release a rewritten draft", and Slack's own `trigger_id` expires in three seconds. Every approval primitive that survived contact with reality has an expiry; heai's has none.

**Worth a glance, not a dependency.** [A2A](https://a2a-protocol.org/latest/specification/) is a real v1.0.0 specification with a sensible task-state vocabulary - `WORKING`, `INPUT_REQUIRED`, `AUTH_REQUIRED`, `COMPLETED`, `FAILED`, `CANCELED`, `REJECTED` - and a `contextId` plus `referenceTaskIds` idea that matches linked flows. Its adoption is enterprise agent platforms, not coding harnesses; no CLI in this study speaks it. Take the words, not the protocol. LangGraph's `interrupt()` is the only resumable pause among the agent frameworks, and it carries a trap worth quoting: on resume *"the graph resumes from the start of the node, re-executing all logic"*, so every side effect before the interrupt replays. A `run` block would hit that exactly. CrewAI's and AutoGen's human input are blocking `input()` calls that vanish when the process dies. A file on disk is better than four of those five.

## 6. `reactor`

Very little to change, and one thing to write down.

**Dedupe is already better than the industry's.** Argo Events keeps a five-minute in-memory cache of delivered event ids and calls that *"'exactly once' in almost all cases"*; Inngest dedupes for 24 hours; Restate keys on an idempotency header for 24 hours. All three windows exist because the state is in memory or a bounded store. reactor's `key` lives in files, so its window is unbounded. Keep it.

**Concurrency groups.** reactor's `debounce`, `limit` and `repeat` govern one rule. Nothing stops two different rules, on one commit, from running `git checkout` in the same worktree. GitHub Actions' [`concurrency: {group, cancel-in-progress}`](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#concurrency) is the shape: a group string plus a policy of queue, cancel or drop, enforced with a lock. This is a failure that will actually happen.

**CloudEvents: align the names, do not adopt the envelope.** The [specification](https://github.com/cloudevents/spec/blob/main/cloudevents/spec.md) requires exactly four attributes - `id`, `source`, `specversion`, `type` - and exists for the rule that producers must make `source` + `id` unique and consumers may treat repeats as duplicates. reactor's `{id, source, kind, key, at, payload}` is already isomorphic except for `specversion`. Adopting it would buy interoperability between producers and consumers written by different organizations, which is not the situation, and would pressure dropping `key` in favour of `source` + `id` - which is the worse design for the dominant case, webhook redelivery, where the provider's id can change between deliveries of one occurrence and consumer-side dedupe identity is what is actually needed. The cheap move is to keep the names aligned so that a `--format cloudevents` flag is a twenty-line mapping the day a real consumer appears, and to write that sentence in the README so it is not re-litigated.

## 7. `pod` and `images/`

**The hook shape has converged, and heai should match it.** Four harnesses independently landed on named lifecycle events, a matcher, a shell command, and JSON on stdin. [Codex CLI](https://learn.chatgpt.com/docs/hooks) declares hooks in `~/.codex/hooks.json`, `.codex/hooks.json` or an inline `[hooks]` table, over the events `SessionStart`, `SessionEnd`, `SubagentStart`, `SubagentStop`, `PreToolUse`, `PostToolUse`, `PermissionRequest`, `UserPromptSubmit`, `PreCompact`, `PostCompact`, `Stop`, `Interrupt`, and every hook receives `session_id`, `transcript_path`, `cwd`, `hook_event_name`, `model` and `permission_mode`, with `tool_name` and `tool_input` added for tool hooks. Cline puts scripts in `.clinerules/hooks/` named after the hook type, also JSON on stdin. Gemini CLI nests a `hooks` object inside `settings.json` **[partially unverified]**. flow's hooks pass environment variables today; adding a JSON envelope on stdin, reusing those field names, would make every script anyone has written for a harness work here too.

**Permission grammars.** [opencode's](https://opencode.ai/docs/permissions/) is the cleanest: `allow | ask | deny` per tool with glob matching, including bash prefixes - `{"bash": {"*": "ask", "git *": "allow", "rm *": "deny"}}`. Amp's adds the interesting action: a rule may *delegate the decision to another program*, which is `heai-architect gate` as a permission backend, exactly. Codex has `sandbox_mode` of `read-only`, `workspace-write` or `danger-full-access` and an `approval_policy`; its older sub-table keys could not be confirmed and are **[unverified]**. Gemini's documentation makes the point worth repeating, that blocklisting is less secure than allowlisting. heai's gate is stricter than all of these because it gates by territory ownership rather than by command string, but expressing its verdict in their vocabulary is what lets a harness call it.

**devcontainers.** The [specification](https://containers.dev/implementors/json_reference/) is real, adopted by VS Code, Codespaces, the `devcontainer` CLI and several cloud agent runners, and its two useful parts are the features registry, prebuilt install steps for common toolchains, and the lifecycle command names: `initializeCommand`, `onCreateCommand`, `updateContentCommand`, `postCreateCommand`, `postStartCommand`, `postAttachCommand`, with `waitFor`. Those six names are exactly the hooks pod needs when it creates a worktree, and reusing them costs nothing. Keep the Containerfile; add an optional sibling. Dagger and Nix are **[unverified]** this session and look like ambition beyond a project whose images are one Containerfile each.

**MCP is the wrong layer for this.** The [specification](https://modelcontextprotocol.io/specification/2025-06-18) at revision 2025-06-18 defines resources, prompts and tools on the server side, sampling, roots and elicitation on the client side - and on permissions it says only that implementors *should*, stating outright that MCP *"cannot enforce these security principles at the protocol level"* while requiring that hosts obtain explicit consent. So the finding is the absence: nobody has standardized permissions, which is why every harness invented its own. Wrapping six CLIs as MCP servers would be a thin layer over an existing command-line surface. The one place where asking permission is an actual protocol method rather than prose is Zed's [ACP](https://agentclientprotocol.com), whose client side has `session/request_permission` alongside `fs/read_text_file` and `terminal/*`; backing and licence are **[unverified]** and it is effectively one vendor's convention.

## 8. Evidence, runs and benchmarks

**There is no standard run record, and the nearest thing is unstable.** OpenTelemetry's GenAI semantic conventions have moved out of the main repository into their own, every `gen_ai.*` attribute is still Development status, and the names have churned twice in two years - `gen_ai.provider.name` is currently displacing `gen_ai.system`. The correct move is to write plain JSONL and *name the fields after the convention* so that shipping them to a collector later is a mapping rather than a migration. Langfuse, OpenLLMetry and Weave all need a server; none documents a file import.

The field set worth writing on a settled run, merging the convention's names with what actually matters:

```
run_id, session_id, task, flow, branch, base_commit, head_commit
started_at, ended_at, duration_ms, duration_api_ms
agent, model, model_resolved, prompt_sha, harness_version, container_image
outcome, exit_code, num_turns, permission_denials
usage: { input_tokens, output_tokens, cache_read_input_tokens,
         cache_creation_input_tokens, reasoning_output_tokens }
cost_usd
evidence: [{ cmd, exit_code, duration_ms, log_path }]
verdicts: [{ by, result, score, notes_path }]
```

Three details earn their place. `prompt_sha`, `harness_version` and `container_image` are the fields everyone omits and then cannot explain last month's numbers. The cache token counts must be separate, because a prompt that looks cheaper has often just hit a warm cache. And `verdicts` is a list so that the gate's verdict and a reviewer's coexist without either overwriting the other. Claude Code's `-p --output-format json` already returns `duration_ms`, `duration_api_ms`, `num_turns`, `total_cost_usd`, `permission_denials` and the four usage fields, which is where the previous report's deferred pod change gets its shape.

**The minimal eval format.** [Inspect](https://inspect.aisi.org.uk/eval-logs.html) is the best model and is file-based: datasets are JSON, CSV or JSONL with `input`, `target`, `id`, `metadata`, repeated runs are first-class through `epochs` with a reducer, and logs are files under a configurable directory. promptfoo contributes the assertion list with a threshold. SWE-bench contributes the verification contract that matters: two named test sets, `FAIL_TO_PASS` for what must flip and `PASS_TO_PASS` for what must keep passing, with predictions and grading in separate files so grading is re-runnable without re-running the agent. Terminal-Bench's successor, Harbor, contributes the interface: the verifier writes `reward.json` into a logs directory, which is the fact-file protocol pod already uses - independent convergence rather than something to adopt. That yields a per-task `task.yaml` with `must_pass`, `must_stay_passing`, a timeout, a network mode, and an epoch count, a runner that drops `result.json`, and a baseline committed to git.

**What is actually known about LLM judges.** Judges agree with humans at roughly the rate humans agree with each other on preference questions ([MT-Bench](https://arxiv.org/abs/2306.05685)), and are close to random on questions where correctness is objectively verifiable ([JudgeBench](https://arxiv.org/abs/2410.12784)). Position bias is severe rather than marginal: swapping the order of two answers flipped one judge's verdict on 66 of 80 queries ([Wang et al.](https://arxiv.org/abs/2305.17926)). Self-preference is real and correlates with the model's ability to recognize its own output ([Panickssery et al.](https://arxiv.org/abs/2404.13076)). The operational consequences are three: never ask a judge what a test can decide; never let the model that wrote the patch judge it, which the map already enforces by making author and reviewer different actors; and when comparing two things pairwise, run both orders.

**Three practices that get skipped and matter most.** First, audit the ground truth. When ninety-three developers screened SWE-bench, 68.3% of samples were filtered out - 38.3% had underspecified problem statements and 61.1% had tests that would fail a valid solution - and nobody had noticed until humans read them. Any fixture set here will be worse than it looks. Second, n greater than one, with the spread reported; agent runs are non-deterministic and a single before-and-after comparison of two prompts is the commonest self-deception in this field. The unbiased pass@k estimator is in the [Codex paper](https://arxiv.org/abs/2107.03374) §2.1 if it is needed. Third, record what was actually run at the time it ran, rather than reconstructing it later.

## 9. What not to build, collected

- Deterministic replay, patching and worker versioning. The journal records transitions, not code; there is nothing to diverge.
- Exactly-once delivery machinery: dedupe windows, persistent event buses, dead-letter sinks. At-least-once plus the existing `key` is the whole answer, and a failed hook's log under `actions/` is already the dead-letter queue.
- A saga or compensation language. Compensation is a transition into a rolling-back state with its own hook.
- Quorum and self-review approval rules. Meaningless at one user.
- Pull-request comment plumbing, intra-file lint rules, and a policy engine. All three exist and are better.
- An external approval service. None binds to content, all add a network dependency and an impersonation surface, and the leading one's vendor has abandoned that product.
- A merge driver or CRDTs for the tracker. One file per record plus a regenerated index is the answer, and it is already built.
- MCP servers wrapping the six CLIs, and the A2A protocol. Take A2A's state words.

## 10. Proposals, in order

1. **AGENTS.md from the map.** Add the actor's globs and the request protocol to `heai-architect context`, and a script that writes `AGENTS.md`. Cheapest item here and the only one that buys interoperability with tools that have never heard of this project.
2. **Content-bound, expiring approvals on `by: [human]`.** Record the blob hash of what was approved, the commit, and an expiry; refuse the transition when the hash moved. This is the one safety property the field has not solved and heai can, because everything is already a file in git.
3. **`on_failure` and `timeout` on a hook, and an exit hook.** Turns a silently parked flow into a visible failed state, and stops long-lived processes leaking when a flow moves on. Retry last, defaulting to off, with ASL's field names.
4. **The definition hash, journaled at start, refused loudly by `settle`.** Answers open question 1 in project.md with the Step Functions model at file scale.
5. **`blocked_by` and a derived ready order in `tasks`**, with cycle rejection at write time, plus a `resolution` key and an honest unrouted state.
